# PANCHVANI — CT1 Content Quality & Trust Recovery (2026-10-16)

## Root problem and safe scope
Earlier Quality CI certified HTML structure, factual self-consistency, unique titles, and calculated clocks, **not independent astronomical accuracy, religious tradition, or useful editorial substance**. The indexable Daily pages included heuristic "Traditional favorable signals" from `lib/day-guidance.ts`, which maps Tithi/Nakshatra to unreviewed activity prescriptions (leadership, commerce, purchases). Daily pages also repeated long algorithmic "Day Fingerprint" and "Local Day Interpretation" paragraphs that read like unique prose but primarily restate geography and fact-card values. See public Mumbai 2026-10-16, source checked 2026-10-16.

## Code action
- Remove unreviewed Daily activity recommendation section from actual SSR markup; do not reinterpret these heuristic mappings as religious authority.
- Remove two long synthetic uniqueness sections ("Day Fingerprint", "Local Day Interpretation") from indexed Daily markup.
- Preserve core V5 fact cards (sunrise, sunset, Tithi, Nakshatra, Yoga, Karana, clock end dates), Rahu, Choghadiya, lunar months, years, dated explanations, cross-family links, independent calendar research and all index eligibility.
- Present a bounded explanation that local weekday windows **are not themselves** full wedding, Vrat or festival-date eligibility, with publicly navigable methodology and accuracy links.
- Add `scripts/content-trust-integrity.mjs` to scan the **entire rendered indexed Daily sitemap**, rejecting regressions to the prior invented taxonomy/unreviewed favorable-advice markup and absence of methodology/accuracy links.
- Integrate counts and URL-specific findings into existing `content-quality-report.json` and mandatory `content-quality-gate.mjs`, so standard GitHub Quality CI validates this on real SSR HTML.
- Preserve permanent external unverified flags, prevent interpreting 0 automatic warnings as externally sourced certification. No mass noindex, no sitemap expansion, no change to production V5 or staging V6.

## Release and GSC constraints
CI proves only that known unsupported claims are absent and technical gates pass. It cannot prove an algorithmic Google penalty nor that this patch will restore ranking. Google Search Console verification is currently blocked by subscription and needs authorized first-party GSC access/exports; traffic chronology and Index Coverage must be compared separately. Review similarity and content-quality artifacts before merge and do not merge if the revised Daily content triggers thin-content or near-duplicate gates. Do not equate longer programmatic copy with trust or originality.
